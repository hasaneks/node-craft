# Backend internationalization

The backend owns its catalogs. Clients own theirs. What they share is the machine contract: error codes, field
paths, enum values and payloads (`node-craft-contract` → `references/locale-contract.md` for the header and
resolution order).

## Catalogs

- No user-facing text hard-coded in code: errors, validation messages, notifications, emails.
- One catalog per locale and namespace: `src/shared/i18n/locales/<locale>/<namespace>.json` (`errors`,
  `validation`, `notifications`, `emails`).
- One library and one resolver for the whole project: `i18next` with Fastify, `nestjs-i18n` or `i18next` in NestJS.
- Keys are stable ids (`errors.RESOURCE_NOT_FOUND`), messages use named parameters (`{{field}}`), plurals use the
  library's plural rules (ICU / `Intl.PluralRules`), not string concatenation.
- CI fails when a supported locale is missing a key that the fallback locale has, or when a code in the error
  registry has no message.
- Missing key at runtime in a supported locale: return the generic safe message **in that locale**
  (`errors.INTERNAL_ERROR` in Turkish), log the missing key with the request id. Never fall through to a raw English
  provider message.

## Storing the user's locale

- `users.preferred_locale` (BCP 47, for example `tr`, `en-GB`) is the user's chosen language. It changes only through
  an explicit profile update endpoint.
- The device language, the persisted preference and the country are different fields; do not overload one.
- `users.time_zone` stores an IANA zone (`Europe/Istanbul`) separately from the locale.

## Formatting

- Dates, times, numbers and currency are formatted with `Intl` using the resolved locale and the user's time zone
  when the backend renders text (emails, PDFs, push bodies). API payloads keep machine formats (ISO 8601, decimal
  strings) and let clients format.
- Case changes in user text use `toLocaleUpperCase(locale)` (Turkish `i`/`İ`, `ı`/`I`).

## Multilingual content

Product content that must exist in several languages gets its own model, for example
`product_translations (product_id, locale, name, description, UNIQUE (product_id, locale))` with a defined fallback.
User-generated content is never presented as translated when it was not.

## Tests

Turkish validation error (code unchanged, Turkish messages), unsupported explicit header with a Turkish profile,
regional variant (`en-GB` → `en`), anonymous request, missing key in a supported locale, locale change before a
queued notification.
